# Assignment use-case coverage

This checklist maps the supplied take-home assignment and stakeholder interviews to the Angular prototype. It distinguishes measured behavior, implementation coverage, deliberate human review, and verified public submission deliverables. Audit date: October 15, 2026.

`Verified` identifies the specific unit, browser, or performance check named in the evidence column. The final local run passed 69 unit tests, the original ten browser workflows, 17 extended browser scenarios, and a real-OCR smoke check of the GitHub Pages subpath build. Automated checks do not replace the human typography assessment. `Implemented` means the implementation and related regression coverage are present; the final correctness regression run is recorded separately from the performance measurements. `Human review` is an explicit prototype boundary. The source repository and public Pages deployment have now been verified; full production certification is outside the assignment scope.

## Speed, batch uploads, and usability

| Stakeholder use case                             | Application behavior                                                                                                                                 | Coverage / evidence                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Return a useful result in about five seconds     | Preloads a worker when the upload form opens and reuses workers for later images.                                                                    | **Verified on this desktop and flat artwork:** first-button-to-result p95 was **1.299 s** in 10 fresh-context trials and **0.787 s** in 20 warm trials. This does not establish a general five-second guarantee for photographs, mobile devices, or slow networks.                                                                                                                                                              |
| Handle 200-300 applications at once              | Accepts up to 300 images plus a CSV containing exactly one application row per image. Matches rows by unique filename.                               | **Verified:** one actual 300-image upload with 300 uniquely named files and a 300-row CSV completed successfully. The files were 50 copies of each of the six fictional PNG artworks, totaling 55,803,300 bytes. This measures queue capacity and throughput, not 300 distinct label designs.                                                                                                                                   |
| Keep a large batch manageable                    | Limits OCR to two real workers, exposes queued/reading states and per-image progress, and keeps results available as they finish.                    | **Verified:** two worker URLs, at most two active reading records, progress between start and completion, and 300 completed records with no OCR failures.                                                                                                                                                                                                                                                                       |
| Produce early results while the batch continues  | Updates each record as soon as OCR and verification finish.                                                                                          | **Verified:** first result observed by **1.709 s**, the 200th by **56.065 s**, and all 300 by **85.293 s**. First/200th observations are upper bounds from approximately 750 ms polling. The 200th timing is a milestone within the 300-image run, not a separate 200-image benchmark.                                                                                                                                          |
| Keep controls responsive during batch processing | OCR runs off the main thread; search and filtering remain available.                                                                                 | **Verified:** 23 search-and-clear interactions during the batch had p50 **69 ms**, p95 **79 ms**, and max **119 ms**. The longest observed main-thread task was **67 ms**.                                                                                                                                                                                                                                                      |
| Preserve the right application for every image   | Requires one matching CSV row for every selected image and rejects duplicate/missing/extra mappings.                                                 | **Verified:** every field in all 300 saved applications matched the corresponding CSV row. Invalid mappings are also checked in the upload component and browser regression suite.                                                                                                                                                                                                                                              |
| Export a useful batch report                     | CSV includes per-field expected/observed values, statuses, OCR confidence/timing, reviewer decisions, and notes.                                     | **Verified:** downloaded CSV had **2,550 field rows**, covered all **300 uploads** and the six demo records, and parsed without CSV errors. Spreadsheet formula-like content is escaped.                                                                                                                                                                                                                                        |
| Support agents with varying technical comfort    | Obvious single and batch upload actions, side-by-side evidence, plain-language status/errors, review guide, searchable queue, and responsive layout. | **Implemented:** existing browser suite covers desktop/mobile navigation, labels, keyboard focus, and review workflows. Usability with actual agents remains unevaluated.                                                                                                                                                                                                                                                       |
| Report invalid uploads clearly                   | Rejects unsupported types, empty/oversized images, oversized batches, duplicate filenames, and invalid CSV structure/values before queuing.          | **Implemented:** 10 MB per image, 250 MB total batch, 300 images, and 2 MB CSV limits, plus required field and mapping validation.                                                                                                                                                                                                                                                                                              |
| Recover from unreadable images or OCR failure    | Shows actionable error/review states, allows a clearer replacement image, bounds worker initialization/recognition, and permits retry/restart.       | Timeout/cancellation/corrupt-image handling is **implemented** and the prior real-OCR smoke check exercises cancellation, corrupt input, and restart. **Verified:** actual corrupt and blank PNGs produce actionable error states; change requests require notes; a valid replacement is read with real OCR on the original record. The benchmark does not deliberately trigger the 20 s recognition timeout.                   |
| Handle imperfect photos if practical             | Resizes large images, can enlarge small inputs, and enables automatic deskew.                                                                        | **Optional / partial:** a real PNG rotated 8 degrees and dimmed by 18% remained readable in a browser regression (95 confidence, 1.599 s in that single observation), and stayed unapproved pending typography confirmation. No representative perspective, curved-bottle, blur, or glare dataset was evaluated. A reviewer may request a sharper, closer photo. Full perspective correction and glare removal are not claimed. |

## Reproduce the measured checks

Run the normal setup/build instructions in the README, start `npm run preview` in one terminal, and run the following sequentially in another:

```sh
node scripts/benchmark-batch.mjs
node scripts/benchmark-latency.mjs
```

The scripts default to installed Microsoft Edge on Windows and Playwright Chromium elsewhere. `PROOF_QA_BROWSER` selects another installed channel, such as `chrome`; `PROOF_QA_URL` selects another preview URL. Both scripts use fresh browser storage and actual form/file-upload actions. Generated 300-image batch inputs use an OS temporary directory and are removed afterward. JSON reports, a CSV download, and a screenshot are written under the ignored `.openai/benchmarks/` directory.

See [performance.md](performance.md) for the measurement definitions, environment, and limitations. The recorded performance run preceded the final verifier/review-control correctness edits; those edits retain the same OCR engine and two-worker queue. A final-build performance rerun is not claimed by the recorded numbers.

## Public deployment verification

On October 15, 2026, the public Pages site passed the ten original workflows and all 17 extended use-case checks in fresh, unauthenticated Edge browser contexts. Actual JPEG, WebP, rotated/dim artwork, blank/corrupt-image recovery, restoration after reload, manual approval, batch validation, and mobile navigation were exercised on the hosted application. The original suite completed real OCR on all six batch PNGs and observed 46 HTTP requests, all to the Pages origin, with zero failed HTTP responses or uncaught application errors.

[Hosted verification evidence](evidence/github-pages-verification.json) records the audited source revision, successful deployment run, and both browser reports. The manual-approval semantics check still explicitly uses a seeded OCR error; the other image cases use the real OCR engine. Hosted smoke timings are individual observations and do not replace the controlled benchmark or establish a general network/device guarantee.
